DOCKER7STAGE - 7-STAGE JENKINS CI/CD PIPELINE & KUBERNETES LAB GUIDE

PROJECT NAMING STANDARDS:
- Local Project Folder: docker7stage (Path: C:\Users\mahesh\Desktop\docker7stage)
- GitHub Repository: docker7stage
- Docker Hub Repository: docker7stage
- Application / Container: docker7stage
- Kubernetes Resources: docker7stage-v1, docker7stage-v2, docker7stage-v3
- Jenkins Pipeline Job: docker7stage-pipeline

THREE JENKINS STAGES (Displayed in Jenkins Stage View):
1. Build and Test
2. Build and Push Docker Image
3. Deploy to Kubernetes

VERSION CONFIGURATION & PORT ALLOCATION:
- Version v1: Docker image tag v1 | Kubernetes: docker7stage-v1 | NodePort: 30081
- Version v2: Docker image tag v2 | Kubernetes: docker7stage-v2 | NodePort: 30082
- Version v3: Docker image tag v3 | Kubernetes: docker7stage-v3 | NodePort: 30083


STAGE 1: PREREQUISITES & WINDOWS JENKINS DOCKER SETUP

1. Verify tools in Windows PowerShell:
   git --version
   python --version
   docker --version
   kubectl version --client
   kubectl get nodes

   Ensure Docker Desktop is running and Kubernetes is enabled in Docker Desktop settings.

2. CRITICAL WINDOWS JENKINS SETUP NOTE:
   If Jenkins is installed as a Windows Service (running under LocalSystem), it will NOT have
   access to Docker Desktop named pipes (\\.\pipe\docker_engine) because Docker Desktop runs
   inside your interactive user session.

   Recommended Solution for Students:
   Download the Jenkins WAR file and run it directly in your user terminal:
   java -jar jenkins.war --httpPort=8080

   This ensures Jenkins runs with your exact user permissions and has full access to:
   - Docker CLI and Docker Desktop daemon
   - Python virtual environments
   - Git and kubectl commands

   Alternative if using Windows Service (services.msc):
   - Open services.msc, right click Jenkins -> Properties -> Log On tab.
   - Choose "This account" and enter your Windows username and password.
   - Restart the Jenkins service so it can communicate with Docker Desktop.

1. Go to https://github.com and create a new repository:

2. In PowerShell inside C:\Users\mahesh\Desktop\docker7stage:

   git branch -M main
   git remote add origin https://github.com/YOUR_GITHUB_USERNAME/docker7stage.git

   (Replace YOUR_GITHUB_USERNAME with your actual GitHub username)


STAGE 4: DOCKER HUB REPOSITORY & ACCESS TOKEN

1. Sign in to https://hub.docker.com
2. Click "Create repository":
   - Name: docker7stage
   - Visibility: Public
   - Click "Create"

3. Generate an Access Token:
   - Click your profile icon top-right -> Account Settings -> Security.
   - Click "New Access Token".
   - Description: jenkins-token
   - Permissions: Read & Write
   - Click "Generate" and copy the token immediately.


STAGE 5: CONFIGURE JENKINS (CREDENTIALS & PIPELINE)

1. Open Jenkins in your browser:
   http://localhost:8080

2. Add Docker Hub Credentials:
   - Go to: Manage Jenkins -> Credentials -> System -> Global credentials (unrestricted).
   - Click "Add Credentials":
     * Kind: Username with password
     * Scope: Global
     * Username: <Your Docker Hub Username>
     * Password: <Your Docker Hub Access Token from Stage 4>
     * ID: dockerhub-credentials
     * Description: Docker Hub Credentials
   - Click "Create".
   (The ID MUST be exact: dockerhub-credentials)

3. Create the Pipeline Job:
   - Click "New Item" from the Jenkins dashboard.
   - Enter name: docker7stage-pipeline
   - Select "Pipeline" and click "OK".
   - Under the "Pipeline" section at the bottom:
     * Definition: Pipeline script from SCM
     * SCM: Git
     * Repository URL: https://github.com/YOUR_GITHUB_USERNAME/docker7stage.git
     * Branches to build: */main
     * Script Path: Jenkinsfile
   - Click "Save".


STAGE 6: RUNNING VERSION 1 (FIRST STOPPING POINT)

1. On the first run, click "Build Now" once.
   This allows Jenkins to read the Jenkinsfile and discover the APP_VERSION parameter.

2. Now click "Build with Parameters":
   - APP_VERSION: v1 (default)
   - Click "Build".

3. Observe the Jenkins Stage View. You will see 3 stages execute:
   [1. Build and Test] -> [2. Build and Push Docker Image] -> [3. Deploy to Kubernetes]

4. Verify Kubernetes resources in PowerShell:

   kubectl get service docker7stage-v1

5. Test Version 1 in your browser:
   http://localhost:30081/
   http://localhost:30081/health

   Expected browser output:
   Docker 7-Stage CI/CD Pipeline - Version 1
   Status: Running


STAGE 7: EXTENDING TO VERSION 2 (COEXISTING DEPLOYMENT)

When your faculty asks to demonstrate Version 2, perform these steps:

1. Update app.py:
   Open app.py and replace its content with:

from flask import Flask, jsonify

app = Flask(__name__)

@app.route("/")
def home():
    return "<h1>Docker 7-Stage CI/CD Pipeline - Version 2</h1><p>Status: Running with Updated Features</p>"

@app.route("/health")
def health():
    return jsonify(status="healthy", version="v2"), 200

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)

2. Create k8s/deployment-v2.yaml:
   Create a new file at k8s/deployment-v2.yaml with this exact content:

apiVersion: apps/v1
kind: Deployment
metadata:
  name: docker7stage-v2
  labels:
    app: docker7stage-v2
    version: v2
spec:
  replicas: 2
  selector:
    matchLabels:
      app: docker7stage-v2
  template:
    metadata:
      labels:
        app: docker7stage-v2
        version: v2
    spec:
      containers:
        - name: docker7stage
          image: DOCKERHUB_USERNAME/docker7stage:v2
          imagePullPolicy: Always
          ports:
            - containerPort: 5000
          readinessProbe:
            httpGet:
              path: /health
              port: 5000
            initialDelaySeconds: 5
            periodSeconds: 5

3. Create k8s/service-v2.yaml:
   Create a new file at k8s/service-v2.yaml with this exact content:

apiVersion: v1
kind: Service
metadata:
  name: docker7stage-v2
  labels:
    app: docker7stage-v2
    version: v2
spec:
  type: NodePort
  selector:
    app: docker7stage-v2
  ports:
    - port: 80
      targetPort: 5000
      nodePort: 30082

4. Commit and push changes to GitHub:
   git add .
   git commit -m "Add Version 2 application and Kubernetes manifests"
   git push

5. Run in Jenkins:
   - Go to docker7stage-pipeline in Jenkins.
   - Click "Build with Parameters".
   - Select APP_VERSION: v2
   - Click "Build".

6. Verify Version 2 in browser:
   http://localhost:30082/
   http://localhost:30082/health

7. Notice: Both Version 1 and Version 2 are running simultaneously:
   kubectl get pods
   kubectl get services
